11. Windows passwords and local credential processing

The Operator does not receive or store the raw Windows password on the Entrix backend or on the iPhone, and the password is not intentionally written to Entrix application logs.

Entrix may keep a salted local password verifier in a protected Windows profile so an incorrect password can be detected before an approval request is sent. Local Windows secrets and state are protected using Windows DPAPI and restricted file-system permissions, as applicable.

12. Entrix PIN and PIN Vault — express local-storage consent

The Entrix PIN is separate from a Windows Hello PIN. If you choose to enable the Entrix PIN / PIN Vault feature, you expressly instruct Entrix to retain an encrypted local copy of the relevant Windows password on that PC so the feature can operate. The current implementation protects the stored value with AES-256-GCM and protects the data key with a non-exportable TPM-backed key. This encrypted password remains local to the Windows computer and is not sent to the Entrix backend or the iPhone.

Enable PIN Vault only on a computer you trust and control. Local storage reduces the need to re-enter the Windows password in some Entrix flows but creates an additional local security asset. Unpairing, account deletion after the PC reconnects, or uninstalling Entrix may remove this data according to the current cleanup behavior described in the Privacy Policy.

13. End-to-end encrypted TOTP and recovery synchronization

Supported TOTP secrets and recovery codes are synchronized between paired devices only as end-to-end encrypted payloads. The synchronization key is held by paired devices and is not stored by the Entrix backend. The server stores ciphertext and cannot decrypt those synchronized secrets. Local copies may still exist on the paired Windows PC and iPhone as described in the Privacy Policy.

14. Enforce mode and lockout risk

Entrix includes a Windows Credential Provider Filter that can hide other Windows sign-in options when Enforce mode is enabled. Enforce is intentionally gated to reduce lockout risk: it takes effect for a Windows user only after that user has completed at least one successful Entrix sign-in; a working TOTP setup and recovery code are required; and for supported Microsoft/Entra account configurations a healthy PIN Vault is required before Enforce can be enabled.

Even with these safeguards, no authentication filter can guarantee access in every hardware, software, Windows-update, credential or recovery state. Losing the iPhone, recovery code and Windows password, or encountering a serious hardware/software failure, can require a Windows Recovery Environment procedure and may also require the BitLocker recovery key. Safe Mode does not bypass Entrix by design.

  • Keep and remember the Windows password independently of Entrix.

  • Keep a working TOTP method and the Entrix recovery code in a safe place and test recovery before enabling stricter protection.

  • Keep Windows administrator and BitLocker recovery options available independently of Entrix.

  • Do not make Entrix the only recovery path for irreplaceable data or a computer whose downtime would create serious harm.

  • Use the documented Windows Recovery Environment procedure if Enforce must be disabled without the backend.

17. Account deletion

Account deletion starts in the iPhone app at Settings → Delete Account and requires a fresh Sign in with Apple from the same Apple ID. A mismatched Apple ID is refused. Once confirmed, the server deletes the Entrix account and account-linked server data, revokes the relevant Apple sign-in authorization where supported, deletes the Supabase sign-in user, and releases each paired PC.

When a released PC next comes online, it normally erases that Windows user's Entrix sign-in profile, TOTP secret, recovery code, PIN Vault, sync key, stored account e-mail and protection settings, then returns to normal Windows sign-in behavior. A PC that remains offline can keep that local data until it reconnects or Entrix is uninstalled. Backup copies containing deleted data expire within 30 days. A deletion marker containing only account ID and deletion time remains for 90 days to stop stale credentials from recreating the account.

Deleting the Entrix account does not cancel an Apple subscription. The user must separately manage or cancel the subscription through Apple. Removing a single computer from the iPhone app releases that computer using the same general cleanup approach.

22. Security measures

Entrix uses layered technical and organizational controls intended to reduce risk. These measures do not guarantee absolute security, but the current implementation includes:

  • TLS for app-to-service transport; the self-hosted origin listens locally behind the Cloudflare tunnel.

  • End-to-end encryption for synchronized TOTP secrets and recovery codes; the backend holds ciphertext only.

  • Apple App Attest on authenticated iPhone account requests; development-build App Attest keys are refused in production.

  • Face ID for Windows sign-in approvals; the phone passcode is not accepted as the approval factor.

  • TPM-backed protection for the optional Windows PIN Vault and Windows DPAPI/restricted folders for local secret state.

  • A local named pipe that accepts only permitted interactive users, SYSTEM and Administrators; network logons are denied.

Entrix may review good-faith reports but does not promise a bounty, payment, response time, waiver, immunity or legal safe harbor beyond rights provided by applicable law. Coordinated private disclosure is encouraged so that vulnerabilities can be investigated and remediated before public discussion.

4. Known technical and operational limitations

  1. Unsigned Windows software and manual updates. The Windows installer/binaries are not yet code-signed and may trigger SmartScreen warnings. There is no automatic updater. Users must obtain releases manually and may verify the published SHA-256 checksum.

  2. Lost or stolen iPhone. There is no per-device Entrix sign-out/revocation today. Face ID blocks sign-in approval without the enrolled face, but someone with the iPhone passcode may be able to open the app and view local recovery material. Cutting off the lost phone currently requires account deletion/re-setup, together with Apple device-security controls.

  3. Server and Cloudflare trust. A Windows approval or release is accepted because the Entrix server reports it; the result is not end-to-end signed by the phone directly to the PC. Cloudflare terminates ordinary TLS and is part of the trusted path. E2EE TOTP/recovery payloads remain independently encrypted.

  4. Offline PC cleanup. If a PC is offline when an account is deleted or a computer is released, local Entrix data can remain on that PC until it reconnects and receives the release state or until Entrix is uninstalled.

  5. Sandbox purchases. Apple sandbox/TestFlight/App Review purchases can unlock Premium without real payment. Production customers use Apple's real App Store billing.

  6. Residual lockout risk. Enforce safeguards reduce but do not eliminate lockout risk. Severe device, Windows, BitLocker, credential or recovery failures can require Windows Recovery Environment and possibly the BitLocker recovery key. Safe Mode does not bypass Entrix.

  7. No independent age verification. Entrix contractually requires users to be at least 16 but does not currently collect date of birth or independently verify age beyond the surrounding Apple account/platform environment.

  8. No absolute security promise. Security controls, encryption, App Attest, TPM/DPAPI protections, rate limits, backups and key rotation reduce risk but cannot guarantee that Entrix is unhackable, always available, immune to third-party compromise, or capable of preventing every unauthorized access event.
